Este capítulo resume as operações de backup, restauração e recuperação, atualização do sistema SAP e replicação assíncrona com o SnapCenter.



[[backup-operations]]
== Operações de backup

As operações de backup são executadas da mesma forma que descrito em https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-backup-operations.html["Saiba mais sobre operações de backup para snapshots do SAP HANA no SnapCenter."].


NOTE: Se nenhum grupo de consistência estiver configurado para a unidade de storage, SnapCenter cria um grupo de consistência e um grupo de consistência filho com a primeira operação de backup de Snapshot. O storage do HANA é então atribuído ao grupo de consistência filho. Os backups de Snapshot do SnapCenter são listados dentro do grupo de consistência filho.

image:hana-sc-bare-metal-asar2-image-007.png["width=601,height=191"]

image:hana-sc-bare-metal-asar2-image-008.png["width=601,height=205"]



[[restore-and-recovery]]
== Restauração e recuperação

As operações de restauração e recuperação são executadas da mesma forma que descrito https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-restore.html["Restaure e recupere bancos de dados SAP HANA com o SnapCenter."].



[[asynchronous-storage-replication]]
== Replicação assíncrona de storage

Para o volume de dados do HANA, foi configurada uma replicação assíncrona de storage.

image:hana-sc-bare-metal-asar2-image-009.png["largura=601, altura=180"]

A replicação foi configurada com a política MirrorAndVault.

image:hana-sc-bare-metal-asar2-image-010.png["width=601,height=206"]

A política MirrorAndVault inclui diferentes rótulos e retenções SnapMirror.

image:hana-sc-bare-metal-asar2-image-011.png["width=601,height=235"]

No SnapCenter, uma política foi configurada para corresponder ao rótulo SnapMirror "daily" da política MirrorAndVault do ONTAP.

image:hana-sc-bare-metal-asar2-image-012.png["width=378,height=354"]

Ao usar a política MirrorAndVault do ONTAP, o SnapCenter exibe cópias separadas de Vault e Mirror, mesmo que os backups de Snapshot estejam disponíveis apenas uma vez no storage de destino.

image:hana-sc-bare-metal-asar2-image-013.png["largura=601, altura=294"]



[[sap-system-refresh]]
== Atualização do sistema SAP

Informações mais detalhadas sobre operações de atualização e clonagem do sistema SAP usando o SnapCenter podem ser encontradas em  https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-introduction.html["Automatizando as operações de clonagem e cópia do sistema SAP HANA com o SnapCenter"].



[[snapcenter-workflow]]
=== SnapCenter fluxo de trabalho

Os detalhes da operação e os pré-requisitos são descritos em  https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-hana-sys-refresh-with-sc.html#prerequisites-and-limitations["Atualização do sistema SAP HANA com o SnapCenter"]. Especificamente, o sistema de destino deve ser adicionado ao SnapCenter antes que você possa executar a primeira operação de atualização/clonagem.

Na primeira etapa do fluxo de trabalho de clonagem, você deve fornecer o host de destino e o SID de destino.

image:hana-sc-bare-metal-asar2-image-014.png["width=333,height=313"]

A seleção do protocolo deve ser "FCP".

image:hana-sc-bare-metal-asar2-image-015.png["width=334,height=312"]

Opcionalmente, você pode adicionar o script sc-system-refresh.sh para automatizar a operação de recuperação.

image:hana-sc-bare-metal-asar2-image-016.png["width=352,height=331"]

A captura de tela abaixo mostra o arquivo de log da tarefa do fluxo de trabalho de clonagem.
